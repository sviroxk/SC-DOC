SC

Краткая документация по реально реализованному подмножеству языка SC. Компилятор написан на C++ и генерирует LLVM IR. Проект развивается; этот сайт не описывает незавершённые функции как готовые.

Исходный код компилятора на GitHub ↗

SC пока прототип. Не используйте его для критичных или production-систем: типизированные массивы, память, диагностика и стандартная библиотека ещё имеют ограничения.

Сборка

Нужны C++ compiler, LLVM development tools и команды llvm-config, llvm-as, llc, clang. В клонированном репозитории:

./build.sh
./test.sh

Сборочный скрипт создаёт исполняемый файл sc. Для дополнительной диагностики поддерживаются переменные окружения:

CXXFLAGS='-Wall -Wextra -Werror' ./build.sh
CXXFLAGS='-Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer' \
  ASAN_OPTIONS=detect_leaks=1 ./test.sh

Первая программа

Создай файл hello.svx:

print("Привет, мир!");

Собери и запусти:

./run.sh hello.svx

CLI-компилятор печатает LLVM IR в stdout. run.sh вызывает LLVM assembler/backend и системный linker, затем запускает программу.

Синтаксис

Новый стиль поддерживает let, fn, return, print, if/else, вызов функции по имени и комментарии //. Точки с запятой нужны для простых statements.

fn add(int left, int right) {
    return left + right;
}

let answer: int = add(20, 22);
print(answer);

В `examples/modern.svx` есть полный исполняемый пример.

Типы данных

Обычные имена — алиасы фиксированной ширины. Целые и float-литералы проверяются на диапазон при прямом присваивании, аргументах и return.

Арифметика узких integer продвигается к 32 битам. Неявное смешение signed/unsigned шириной от 32 бит запрещено. Явный числовой cast записывается как (i8) value. Cast вычисляемого значения в более узкий тип может усечь данные; runtime checked cast не реализован.

Функции

Неаннотированная функция возвращает int. Тип результата указывается перед именем; процедуре пишут void. Non-void функции должны возвращать значение по проверяемым прямым веткам.

fn int square(int value) {
    return value * value;
}

fn void announce() {
    print("Готово");
}

let result: int = square(7);
print(result);
announce();

Параметры типизированы. Арность и совместимость аргументов проверяются перед генерацией LLVM.

Условия, логика и циклы

int count = 0;
cert usy (count < 3) {
    count = count + 1;
}

if (count >= 3 && !(count == 4)) {
    print("условие выполнено");
} else {
    print("иначе");
}

Доступны `<`, `>`, `<=`, `>=`, `==`, `!=`, `&&`, `||`, `!`, `+ - * / %`. У `&&` и `||` short-circuit semantics. Новые циклы пока имеют legacy-запись `cert usy (...)` и `cert ceh (...)`; `for ... in range` не реализован.

Массивы

svi rox[] lor values = [10, 20, 30];
print(values[0]);
values[1] = 42;
print(values[1]);

В текущем backend массивы — i32 storage. Для статических массивов чтение и запись проверяют отрицательные и верхние индексы во время выполнения. Динамические массивы через `ptr` не несут длину и bounds-check для них отсутствует.

Структуры

tip Player {
    rox health = 100;
    rox speed = 5;
}

svi tip Player lor hero;
hero.health = 80;
slov(hero.health);

Поддерживается legacy-объявление структуры с полями и значениями по умолчанию, создание экземпляра и доступ к полям через точку. Точные типы в aggregate storage пока не поддержаны.

Импорты

imp "../stdlib/math/math.svx";
let magnitude: long = math_abs(-17);
print(magnitude);

Пути разрешаются относительно импортирующего файла; вложенные импорты допустимы, повторные файлы загружаются один раз. Циклы и отсутствующие файлы дают ошибку. `use`, namespaces, `pub`, selective imports и отдельная компиляция модулей пока отсутствуют.

Библиотека

Начальный модуль находится в stdlib/math/math.svx. Проверены функции math_abs(int) -> long, math_min(long,long), math_max(long,long) и math_is_even(long). Абсолютное значение минимального i32 расширяется до i64 до отрицания.

Для остальных возможностей смотри актуальный backlog. Полной string/collection/fs/io/network stdlib ещё нет.

Ошибки и диагностика

Семантическая ошибка выводится с путём файла, строкой и столбцом, например main.svx:4:1: error[semantic]. Lexer/parser сообщают первую найденную синтаксическую ошибку и завершаются; восстановление для нескольких syntax errors пока не реализовано.

Статический массив при выходе за границы печатает runtime-сообщение с source coordinates и завершает программу с ненулевым кодом. Ошибки OOM в строковом `rep` пока завершают программу через abort.

Что ещё не готово

  • SC — экспериментальный прототип, не стабильный production-язык.
  • Нет `sc build/run/test`, package manager, formatter, LSP, debugger или self-hosting.
  • Нет полноценной ownership/memory-safety модели; raw pointers небезопасны.
  • Точные числовые типы пока ограничены скалярными значениями и функциями.
  • Нет namespace imports, generics, enum, Option/Result, closures или methods.
  • Стандартная библиотека содержит только небольшой source-based math-модуль.
  • Арифметическое переполнение вычисляемых значений не проверяется runtime.
